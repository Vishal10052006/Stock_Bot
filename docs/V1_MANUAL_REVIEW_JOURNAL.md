# V1 Manual Review & Outcome Journal\n\n## Purpose\n\nThe V1 signal is a real-market decision-support artifact. The human operator\nreviews it and manually decides whether to act. The journal preserves that\nhuman boundary as auditable evidence.\n\nThe journal does **not** place, modify, cancel, or infer broker orders.\n\n## Evidence flow\n\n    V1SignalContract\n          |\n          v\n    ManualReviewRecord\n          |\n      ACCEPT / REJECT\n          |\n          +--------------------+\n          |                    |\n          v                    v\n    manual execution      no execution\n          |\n          v\n    ManualOutcomeRecord\n          |\n          v\n    later analysis / learning evidence\n\nAn ACCEPT review is **not** an executed trade. A ManualOutcomeRecord exists only\nwhen the operator explicitly supplies observed execution/outcome facts.\n\n## ManualReviewRecord\n\nEach review captures:\n\n- canonical signal_id;\n- signal fingerprint as observed by the reviewer;\n- signal timestamp and validity boundary;\n- symbol and BUY/SELL/WAIT signal;\n- Entry / Stop Loss / Target / R:R;\n- confidence and real prediction evidence;\n- supporting and contradicting factors;\n- risk conditions;\n- provenance;\n- human action: ACCEPT or REJECT;\n- optional human review note.\n\nThe record is immutable and persisted append-only as JSONL.\n\n## ManualOutcomeRecord\n\nA later outcome is a separate immutable event linked by review_id and\nsignal_id.\n\nThe bot does not manufacture this record. The caller must explicitly provide:\n\n- observation timestamp;\n- lifecycle status;\n- execution timestamp and entry price when executed;\n- quantity when executed;\n- exit timestamp/price and net P&L when closed;\n- fees/slippage when known;\n- operator note.\n\nThis prevents the common failure where an accepted recommendation is incorrectly\ncounted as an executed trade.\n\n## Integrity rules\n\n- timezone-aware timestamps are mandatory;\n- numeric values must be finite;\n- prices and quantities must be positive when supplied;\n- fees and slippage must be non-negative;\n- executed outcomes require explicit execution facts;\n- closed outcomes require explicit exit and net-P&L facts;\n- duplicate journal events are rejected;\n- records are append-only;\n- no broker API/client/order operation is imported or called.\n\n## Relationship to Phase 16\n\nPhase 16 remains the authoritative Strategy/Paper TradeDecisionRecord /\nTradeJournalRecord memory path.\n\nThis V1 journal is a separate human-review evidence boundary because V1 manual\nreal-money review must not be represented as a paper fill or as an automatic\nexecution event.\n\nThe two paths can later be correlated through explicit provenance, but this\nmodule never converts a manual review into a paper or broker transaction.\n\n## Safety boundary\n\nACCEPT means only:\n\n> the human reviewer accepted the V1 setup for possible manual action.\n\nIt does not mean:\n\n- broker order submitted;\n- trade executed;\n- fill confirmed;\n- position opened;\n- profit/loss realized.\n\nThose facts require explicit external/manual observation.\n\n## Validation\n\nFocused tests cover:\n\n- exact V1 signal capture;\n- ACCEPT / REJECT actions;\n- append-only persistence;\n- duplicate rejection;\n- explicit outcome linkage;\n- rejection of incomplete execution facts;\n- absence of broker order operations.\n
