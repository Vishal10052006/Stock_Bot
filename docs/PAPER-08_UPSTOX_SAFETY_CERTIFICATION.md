# PAPER-08 — E17 Upstox Adapter + Safety Certification\n\n## Purpose\n\nCertify the provider-facing Upstox adapter boundary together with the independent execution safety gate.\n\n## Certification matrix\n\n| Case | Requirement |\n|---|---|\n| live_is_locked_by_default | Live execution remains disabled by default |\n| kill_switch_blocks_even_when_live_enabled | Kill switch has precedence |\n| stale_data_blocks_before_provider_routing | Stale market data blocks execution |\n| invalid_data_quality_blocks | Invalid data quality blocks execution |\n| closed_session_blocks | Closed market session blocks execution |\n| provider_disabled_is_fail_closed | Disabled Upstox adapter cannot route calls |\n| enabled_provider_requires_injected_client | Adapter never constructs credentials/client internally |\n\n## Provider boundary\n\nThe existing UpstoxBrokerAdapter remains broker-neutral at the execution engine boundary. It maps OrderRequest to an Upstox payload and maps provider states/fills/positions back into canonical execution contracts.\n\nCredentials and HTTP/SDK construction remain outside the execution domain.\n\n## Safety boundary\n\nIndependentSafetyGate is evaluated independently of strategy/model output. It blocks on kill switch, stale data, invalid data quality, closed session, and live lock.\n\nThe certification intentionally does not make live_execution_enabled=True a production approval. The broader production readiness gates remain authoritative.\n\n## Live trading status\n\n**LOCKED.**\n\nThis certification performs no live Upstox order submission. The Upstox SDK transport remains sandbox-only, and production readiness still requires all required gates to pass.
