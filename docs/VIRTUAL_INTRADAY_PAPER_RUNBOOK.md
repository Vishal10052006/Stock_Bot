# STOCK_BOT — Virtual Intraday Paper Trading Runbook\n\n## Purpose\n\nRun STOCK_BOT against the real-time Upstox market-data feed while all trading\ncapital remains virtual.\n\nDefault virtual capital:\n\n    ₹100,000\n\nThe virtual session does not submit broker orders.\n\n## Session boundary\n\nFor NSE equities, the normal market session is 09:15–15:30 IST. STOCK_BOT's\nvirtual session defaults to that outer observation window.\n\nThe existing paper exit engine retains its configured **15:15 IST session\ncutoff** for intraday position lifecycle management. Therefore:\n\n- market observation can continue through the configured session close;\n- new/active intraday positions are subject to the existing 15:15 cutoff;\n- the final session close reconciliation must leave zero open positions.\n\nReference: NSE market timings:\nhttps://www.nseindia.com/static/market-data/market-timings\n\n## Runtime architecture\n\n    Upstox Market Data V3\n            ↓\n    RealtimeMarketDataPipeline\n            ↓\n    Completed 5-minute Candle\n            ↓\n    CanonicalLivePaperOrchestrator\n            ↓\n    Market Bot\n            ↓\n    Analysis\n            ↓\n    Prediction\n            ↓\n    Canonical Paper Callback\n            ↓\n    Strategy\n            ↓\n    Risk\n            ↓\n    Independent Safety\n            ↓\n    PaperTradingRuntime\n            ↓\n    VirtualIntradaySession\n            ↓\n    Account Ledger + Summary\n\nThe virtual-session wrapper does not implement a second Strategy, Risk, or\nexecution policy.\n\n## Account outputs\n\nEach session is written below:\n\n    paper/virtual_sessions/<session-id>/\n        account_ledger.jsonl\n        account_summary.json\n\n`account_ledger.jsonl` records:\n\n- timestamp;\n- equity;\n- realized P&L;\n- unrealized P&L;\n- gross exposure;\n- open positions.\n\n`account_summary.json` records the final reconciled account state,\ncompleted-trade count, and a deterministic SHA-256 fingerprint.\n\n`live_broker_orders` must remain `0`.\n\n## Persisted-session validation\n\nAfter a session:\n\n    python scripts/validate_virtual_session.py \\n        paper/virtual_sessions/<session-id>\n\nThe validator fails closed if:\n\n- the ledger is empty;\n- timestamps are not chronological;\n- account values are non-finite;\n- exposure or positions are negative;\n- the final account has open positions;\n- final unrealized P&L is non-zero;\n- final equity does not reconcile to initial equity + realized P&L +\n  unrealized P&L;\n- summary values disagree with the final ledger row;\n- the summary fingerprint is invalid;\n- any live broker order is recorded.\n\n## Safety invariant\n\nThe virtual session must never be treated as live execution.\n\n    Virtual account\n        ≠\n    Broker account\n\nA successful paper session demonstrates software/data-flow operation. It does\nnot establish profitability, model robustness, or permission to trade\nreal capital.\n\n## Tomorrow's operational sequence\n\n1. Synchronize `main`.\n2. Confirm the Upstox access token and instrument mapping are valid.\n3. Run the repository readiness command.\n4. Start the real-market paper session.\n5. Keep broker execution locked.\n6. Capture the complete session ledger.\n7. Run `validate_virtual_session.py`.\n8. Review signals, fills, rejections, P&L, exposure, exits, and monitoring\n   evidence.\n9. Preserve the session artifacts as evidence.\n10. Only then decide which software boundary needs the next hardening pass.
