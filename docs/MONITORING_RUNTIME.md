# Monitoring Runtime Integration\n\n## Purpose\n\n`monitoring.runtime.MonitoringRuntime` is the runtime collection boundary for the central Monitoring Engine.\n\nProducer telemetry flows one way:\n\n`Market / Data / Analysis / Model / Strategy / Risk / Execution -> MonitoringRuntime -> MonitoringPipeline -> MonitoringEngine -> Metrics / Alerts / Dashboard / Journal`\n\nMonitoring is observation-only. It does not authorize or reject orders, size positions, change strategy/model/risk parameters, submit broker orders, or promote models.\n\n## Runtime entry points\n\n- `observe_market()` — Market Bot health, quality, latency.\n- `observe_analysis()` — Analysis Bot health and feature-quality telemetry.\n- `observe_data_quality()` — market data error/stale/duplicate/gap monitoring.\n- `observe_analysis_quality()` — feature completeness/drift monitoring.\n- `observe_prediction()` — one prediction event mapped into model telemetry without trade authority.
- `observe_model()` — prediction accuracy/calibration/distribution monitoring.\n- `observe_strategy()` — strategy decision/trade telemetry.\n- `observe_risk()` — risk utilization and limit observations.\n- `observe_execution()` — fill/rejection/latency/slippage observations.\n- `observe_performance()` — return, drawdown, expectancy and benchmark telemetry.\n- `observe_regime()` — regime distribution and shift telemetry.\n- `report()` — readiness + validation + dashboard payload.\n- `dashboard()` — JSON-safe current monitoring state.\n\n## Readiness\n\nReadiness is evidence-based. A runtime report requires a valid monitoring snapshot and at least one observed component health record. Missing system/data evidence can produce a BLOCKED monitoring-readiness state.\n\nThis readiness state is not the trading Safety Gate and does not replace Risk or Independent Safety.\n\n## Operational deployment\n\nThe Market Bot, Analysis Bot integration seam, and Prediction Inference Service now accept the runtime bridge directly. The authoritative Paper Decision Loop already uses the same boundary for Strategy/Risk/Execution. A deployment entry point should construct one shared `MonitoringRuntime` and pass it through all participating producers so the dashboard represents one coherent run.\n\nPersistent `MonitoringJournal` storage remains optional at engine construction and must be configured by the application runtime when durable telemetry is required.
