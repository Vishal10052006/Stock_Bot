# Live Prediction Validation\n\n## Purpose\n\nThis module adds the missing evidence loop for real-market predictions:\n\n    completed live candle\n        -> causal prediction\n        -> immutable prediction journal\n        -> wait for the complete Phase 7 horizon\n        -> resolve the actual Phase 7 outcome\n        -> compare predicted class vs actual class\n        -> accuracy/confusion report\n\nThe implementation is prediction validation only. It does not submit, modify,\nor cancel broker orders.\n\n## Outcome semantics\n\nThe resolver reuses the repository's Phase 7 `label_decision(...)` contract.\n\nThe default frozen policy is:\n\n- target: 1.5R;\n- horizon: 12 completed 5-minute bars;\n- LONG_SUCCESS when only the long candidate succeeds;\n- SHORT_SUCCESS when only the short candidate succeeds;\n- NO_EDGE when neither succeeds;\n- earlier success wins when both succeed on different bars;\n- same-bar directional ambiguity is NO_EDGE.\n\nA live prediction remains `PENDING` until all 12 future bars are available.\nA missing future bar is never converted into a fabricated NO_EDGE result.\n\n## Causal boundary\n\nThe prediction timestamp itself is excluded from the outcome window.\nOnly candles with `candle.timestamp > prediction.timestamp` are eligible.\n\nCausal candidate prices and stops are captured at prediction time so later\noutcome evaluation does not recompute historical decision inputs.\n\n## Journal\n\n`LiveValidationJournal` stores one append-only JSONL stream:\n\n- `PREDICTION` events contain model probabilities, model/version metadata,\n  horizon policy, and causal candidate evidence.\n- `OUTCOME` events contain PENDING or RESOLVED state.\n\nThe existing `ml/prediction/storage.py` remains prediction-only; live outcomes\nare intentionally stored in this separate journal.\n\n## Report\n\nRun:\n\n    python scripts/evaluate_live_predictions.py \\n        --journal data/live_validation/predictions.jsonl\n\nThe report includes total/resolved/pending predictions, correct/incorrect\ncounts, accuracy, class breakdown, and a confusion matrix.\n\nThe report describes predictive classification quality. It is not a claim of\nprofitability or authorization for live capital.\n\n## Integration contract\n\nThe validation engine accepts:\n\n1. an existing prediction;\n2. the exact decision-time indicator row used to construct that prediction;\n3. later completed market candles for the same symbol.\n\nThis keeps the prediction layer free of future data while allowing an\nindependent outcome/evidence layer to determine correctness.\n\n## Real-market operation\n\nThe repository already contains the Upstox real-time feed, event validation,\nand candle aggregation path. The intended SHADOW flow is:\n\n    Upstox WebSocket\n        -> MarketEvent\n        -> validated completed candle\n        -> existing Phase 4/5/6 causal analysis\n        -> existing Phase 9 prediction\n        -> LiveOutcomeResolver.create_prediction(...)\n        -> LiveValidationJournal.append_prediction(...)\n        -> after 12 future candles:\n           LiveOutcomeResolver.resolve(...)\n        -> LiveValidationJournal.append_outcome(...)\n        -> LivePredictionEvaluator.evaluate(...)\n\nNo broker execution path is required for this validation stage.\n\n## Safety\n\nThis implementation does not enable live order submission. Existing live-order\nlocks and broker boundaries remain unchanged.
