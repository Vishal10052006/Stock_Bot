# V1 Live Runtime Hardening\n\n## Purpose\n\nThe V1 real-market manual-review runtime must start only from explicit operator\nconfiguration. It must never infer a trading identity or silently reuse a\nsynthetic account value.\n\n## Explicit runtime identity\n\n`live-review` requires all of the following to be supplied explicitly:\n\n- symbol;\n- benchmark symbol;\n- model version;\n- verified model artifact path and SHA-256;\n- data version;\n- feature version.\n\nThe CLI may retain historical defaults for legacy modes, but those defaults are\nnot used to construct a V1 `live-review` runtime.\n\n## Account-state boundary\n\nThe V1 manual-review dashboard/runtime uses verified live account context.\nSynthetic `initial_equity` is rejected when\n`require_live_account_context=True`.\n\nThe initial waiting snapshot therefore reports:\n\n- `ACCOUNT_STATE_UNAVAILABLE`;\n- no initial equity;\n- no synthetic equity;\n- no synthetic return.\n\nOnce the live account observer supplies state, the snapshot publishes only the\nobserved account values.\n\n## Safety invariant\n\nAn explicit runtime identity and an observed live account context are separate\nrequirements:\n\n1. runtime identity prevents accidental symbol/model substitution;\n2. live account context prevents paper/synthetic capital from entering V1;\n3. the existing Risk freshness gate remains authoritative;\n4. broker order submission remains disabled.\n\n## Verification\n\nFocused tests cover:\n\n- missing V1 symbol/benchmark/model identity;\n- rejection of synthetic `initial_equity`;\n- waiting snapshots without synthetic equity;\n- normal manual-review routing remaining outside paper execution.
