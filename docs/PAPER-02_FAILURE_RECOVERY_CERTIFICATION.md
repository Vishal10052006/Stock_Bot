# PAPER-02 — Failure & Recovery Certification\n\n## Scope\n\nPAPER-02 certifies deterministic failure semantics after PAPER-01. It uses the existing `FailureMatrixReport` and `validate_failure_matrix` contract rather than creating a second retry or reconciliation mechanism.\n\n## Certified scenarios\n\n- `TIMEOUT` → `UNKNOWN`.\n- `NETWORK_ERROR` → `UNKNOWN`.\n- Missing broker state during recovery remains `UNKNOWN`.\n- Recovery does not submit the order again.\n- `BROKER_REJECTION` remains `REJECTED_BROKER`.\n\n## Safety property\n\nAn ambiguous submission is not interpreted as a failed order that may simply be resubmitted. Broker truth must resolve the state first.\n\n## Evidence\n\nTest: `tests/execution/test_failure_recovery_certification.py`\n\nImplementation: `execution/failure_recovery_certification.py`\n\nLive broker execution remains locked. PAPER-02 is a failure/recovery certification milestone only.
